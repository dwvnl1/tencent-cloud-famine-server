## 腾讯云饥荒服务器有哪两条路，分别适合谁

一键开服适合不想管系统的人；自建适合想完全掌握存档、MOD 和启动参数的人。前者在轻量云游戏服专区完成，后者本质上就是买一台 CVM 或轻量应用服务器当游戏主机。

一键开服的流程大致是这样：登录轻量云游戏服专区，在首页游戏列表里选《饥荒》，再选游戏套餐、地域、服务器时长和是否自动续费。开好之后你还需要一个 Klei 的服务器 Token——登录 Klei 官网，找到「游戏 >《饥荒：联机版》」，进入游戏服务器页面创建专属 Token。进游戏时在 Steam「库」里右键饥荒联机版，打开「属性」，在启动选项里填 `+connect IP:端口`，IP 和端口用专区里复制的登录凭证。腾讯云的游戏服专区目前上架了近 20 款热门联机游戏，饥荒是其中之一。

自建这条路要多做几步：用 SteamCMD 拉取 Don't Starve Together Dedicated Server（`app_update 343050`），然后配置 `cluster_token.txt` 和 `server.ini`。存档目录在 `/root/.klei/DoNotStarveTogether`，服务器 MOD 目录在 `/root/Steam/steamapps/common/Don't Starve Together Dedicated Server/mods`。

## 配置怎么选：核心数不是关键，单核性能和内存才是

《饥荒》服务端的优化决定了它吃不满多核，单核性能才是关键指标。所以看到「8 核」就以为能带更多人，是常见的误判——多出来的核心大部分时间在闲置。

按实际测试经验，中型联机（6–12 人）的饥荒联机版大致需要 2 核 4G 这个档位。如果想省钱，1 核 1G 的入门配置也能跑起来，早期用两台 1 核 1G 分别承载地上和地下世界的方案就跑得通，代价是地图规模、MOD 数量和人数都要克制。

带宽比 CPU 更容易被忽略。最低 1Mbps 能开服，但推荐 5–10Mbps，人多、MOD 大、世界物件多的时候，带宽不足会直接表现为卡顿和延迟抖动。自建方案的实际体验可以做到 ping 低于 50，而传统「主机开房间」的联机方式经常在 200ms 以上。

| 玩家人数 | 建议配置 | 带宽 | 说明 |
| --- | --- | --- | --- |
| 2–4 人，纯净档 | 1 核 1G | 1–5Mbps | 入门够用，别装太多 MOD |
| 4–8 人，少量 MOD | 1 核 2G 或 2 核 2G | 5Mbps | 单核主频优先 |
| 6–12 人，含洞穴 | 2 核 4G | 5–10Mbps | 洞穴单独跑会更稳 |
| 12 人以上 | 地上地下分机器部署 | 10Mbps | 两台机器通过端口互联 |

## 端口与安全组：连不上有九成卡在这一步

饥荒联机版默认走 **UDP 10999**，不是 TCP。很多教程只写了 TCP 10999，结果服务端日志看着一切正常，客户端就是连不上。

腾讯云的安全组要这样配：

1. **入站规则**放通 UDP 10800–12000 端口段（覆盖游戏端口和洞穴通信端口），而不是只开一个 10999。
2. **出站规则**放通全协议，不要只放 TCP。地上世界和洞穴世界之间的 shard 通信走的是 UDP。
3. 如果你在 `server.ini` 里改过端口，安全组要跟着改，两边对不上一样连不上。

还有一个容易被误判的情况：安全组全放通了，日志里洞穴的请求也发出去了，但状态一直显示 `inactive`（正常应该是 `active` 或 `disable`）。这时候可以换手机热点试一下——如果热点能起来、宽带起不来，多半是运营商封了部分 UDP 端口。有玩家在青岛电信申请了公网 IP 后遇到这个情况，安全组放通 10800–12000 依然无效，换成热点立刻成功。这种只能找运营商，或者临时先用热点把洞穴拉起来、再切回宽带。

## 洞穴进不去，按这个顺序排查

洞穴被藤蔓缠住进不去，通常是四个原因之一，按下面的顺序查最快出结果。

**第一，洞穴根本没启动。** Windows 端搭建的话，多半是启动脚本只跑了 Master，没跑 Caves。一个可用的 bat 脚本长这样：

bat
@echo off
cd /d %~dp0
cd "steamapps\common\Don't Starve Together Dedicated Server\bin"
start "Master" dontstarve_dedicated_server_nullrenderer -console -cluster MyDediServer -shard Master
start "Caves" dontstarve_dedicated_server_nullrenderer -console -cluster MyDediServer -shard Caves


**第二，cluster_key 还是默认值。** 打开 `server.ini`，把 `[SHARD]` 下面的 `cluster_key` 从 `defaultpass` 改成自己的密钥，Master 和 Caves 两边必须一致：

ini
[SHARD]
cluster_key = supersecretkey


**第三，端口冲突。** 启动了两个服务端实例却用了同一个端口，日志里能看到端口被占用。Master 和 Caves 必须用不同端口。

**第四，防火墙或运营商。** 就是上一节说的情况，入站 UDP 10800–12000、出站全协议，再确认运营商没封端口。

## MOD、存档和管理员权限：自建才需要操心的部分

自建服务器最大的价值在这里：你能把本地调好的世界设置和 MOD 配置直接搬到服务器上，而不用在服务器上一条条改 lua。

这套做法可以叫「移植法」。在本机开一个新存档，按自己想要的方式调好资源、勾好 MOD，进游戏后退出，本地就会生成配置文件。回到游戏主页面点左下角「数据」，打开存档目录，找到刚生成的那个 Cluster 文件夹：

- 地上资源：`Cluster_1/Master/leveldataoverride.lua`，覆盖上传到服务器的 `/root/.klei/DoNotStarveTogether/你的存档名/Master/`
- 洞穴资源：`Cluster_1/Caves/leveldataoverride.lua`，覆盖到对应的 `Caves/` 目录
- 地上 MOD：`Cluster_1/Master/modoverrides.lua`
- 洞穴 MOD：`Cluster_1/Caves/modoverrides.lua`

配置文件传完还不算完，MOD 的源文件也要一起传：本地 `Steam\steamapps\common\Don't Starve Together\mods` 里的内容，上传到服务器的 `/root/Steam/steamapps/common/Don't Starve Together Dedicated Server/mods`。两边都到位，重新登录游戏才会生效。

有个细节值得单独提：如果 `Caves` 目录里留着 `worldgenoverride.lua`，它的优先级高于 `leveldataoverride.lua`，你改的资源设置会被无视，系统仍然按全默认资源生成世界。想自定义资源，先把这个文件删掉。

资源和 MOD 都是「上传配置」这一步完成，但世界本身在开服时已经生成好了，要让新设置生效，得进游戏按 `Tab` 打开面板，点 `···`，再点「生成世界」重新生成。

管理员、白名单、黑名单都是纯文本文件，放在存档根目录：

- `adminlist.txt`：写入 Klei 用户 ID，进游戏点「账户」能看到自己的 ID。有管理员权限才能在服主不在时回滚世界。
- `whitelist.txt`：预留位置。服务器 8 人上限、设 2 个白名单，普通玩家就只能进 6 个，白名单的人不在线也占位。
- `blocklist.txt`：封禁恶意玩家，ID 可以在日志里找到。最简单的办法还是游戏里按 `Tab` 直接踢。

## 常见问题

**一台服务器能同时跑地上和地下吗？**
能，但负载会明显上升，卡顿概率变高。预算够的话拆成两台机器分别跑 Master 和 Caves，容纳人数能提升 1.5 到 2 倍，延迟和卡顿也会好一些。

**WeGame 版能用同样的方法吗？**
WeGame 的《饥荒联机版》支持独立服务端，SteamCMD 拉的是 `app_update 343050`（Don't Starve Together Dedicated Server），配置逻辑一致。

**服务器开着，我下线了朋友还能玩吗？**
能。这正是专用服务器相比「自己开房间」的核心差别——主机不必在线，服务器 24 小时跑着。

**MOD 装了没反应？**
八成是只传了 `modoverrides.lua`，没传 MOD 源文件。两个都要上传，然后重新登录。

**能一台机器换着玩别的游戏吗？**
可以。腾讯云轻量云游戏服专区上架了近 20 款联机游戏，生存建造类里有饥荒、雾锁王国、英灵神殿、我的世界 Java 版等，换游戏时在专区里重新选就行，不用重复买机器。
